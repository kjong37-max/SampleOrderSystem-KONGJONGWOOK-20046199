# 반도체 시료 생산주문관리 시스템 - 요구사항 분석

> 출처: ProjectRequest.pdf (mincoding 개인과제), 1~22페이지 분석

---

## 1. 프로젝트 배경

가상 반도체 회사 **S-Semi**는 다양한 반도체 시료(Sample)를 생산해 연구소·팹리스(Fabless)·대학 연구실 등 고객에게 납품한다. 시료는 웨이퍼 공정 설비로 제작 후 검수를 거쳐 출고된다.

주문량 급증으로 엑셀·메모장 기반 관리의 한계(실수 빈발, 재고·공정 현황 파악 어려움)가 드러나, 체계적인 **반도체 시료 생산주문관리 시스템**을 개발하기로 결정했다.

---

## 2. 역할 구조

| 역할 | 역할 설명 | 주요 행위 |
|------|-----------|-----------|
| 고객 | 시료 요청자 | 이메일로 필요한 시료 요청 |
| 주문 담당자 | 주문서 관리 | 요청에 맞게 주문서 작성·관리 |
| 생산 담당자 | 시료 생산·승인 | 개발 시료 등록, 주문 수신 후 승인/거절 |

시스템은 **주문 담당자와 생산 담당자**가 직접 콘솔 명령을 입력하여 운용한다.

---

## 3. 주문 상태 흐름

```
주문 등록 → [RESERVED]
              ↓
          승인 여부
         /         \
      거절          승인
        ↓             ↓
   [REJECTED]    재고 확인
                /         \
           재고 충분      재고 부족
               ↓               ↓
          [CONFIRMED]     [PRODUCING]
               ↓               ↓ (생산 완료)
          [RELEASED] ←─────────┘
               ↓
            고객 도달
```

| 상태 | 의미 |
|------|------|
| `RESERVED` | 주문 접수 완료 |
| `REJECTED` | 주문 거절 (모니터링 제외) |
| `PRODUCING` | 승인 완료, 재고 부족으로 생산 중 |
| `CONFIRMED` | 승인 완료, 출고 대기 중 |
| `RELEASED` | 출고 완료 |

## 4. 도메인 모델

### 4.1 Sample (시료)

시스템의 가장 기본 단위. 등록된 시료만 주문 가능.

| 필드 | 설명 |
|------|------|
| 시료 ID | 고유 식별자 (예: `S-001`) |
| 이름 | 시료명 (예: `실리콘 웨이퍼-8인치`) |
| 평균 생산시간 | 단위: `min/ea` |
| 수율 | 정상 시료 / 총 생산 시료 (예: `0.92`) |
| 현재 재고 | 현재 보유 수량 (`ea`) |

### 4.2 Order (주문)

| 필드 | 설명 |
|------|------|
| 주문번호 | 자동 생성 (형식: `ORD-YYYYMMDD-NNNN`) |
| 시료 ID | 주문 대상 시료 |
| 고객명 | 주문 고객 |
| 주문 수량 | 요청 수량 (`ea`) |
| 상태 | `RESERVED` / `REJECTED` / `PRODUCING` / `CONFIRMED` / `RELEASED` |

### 4.3 ProductionLine (생산 라인)

- 단일 생산 라인 운영
- 한 번에 시료 하나씩 생산 (순차 처리)
- 주문이 들어온 시료에 대해서만 생산

**생산량 계산 공식:**
```
부족분      = 주문 수량 - 현재 재고
실 생산량   = ceil(부족분 / (수율 × 0.9))   ← 0.9는 보정 상수(고정)
총 생산시간 = 평균 생산시간 × 실 생산량
```

생산 완료 시 주문 상태: `PRODUCING` → `CONFIRMED`

**생산 큐 스케줄링 전략: FIFO**

## 5. 기능 명세

### 5.1 메인 메뉴 구성

| 번호 | 메뉴 | 기능 |
|------|------|------|
| [1] | 시료 관리 | 시료 등록·목록 조회·이름 검색 |
| [2] | 시료 주문 | 고객 주문 접수 (RESERVED 생성) |
| [3] | 주문 승인/거절 | RESERVED 주문 목록 확인 후 승인·거절 처리 |
| [4] | 모니터링 | 상태별 주문 수 및 시료별 재고 현황 확인 |
| [5] | 생산라인 조회 | 현재 생산 중 시료 및 대기 큐 확인 |
| [6] | 출고 처리 | CONFIRMED 주문에 대해 출고 실행 |
| [0] | 종료 | 프로그램 종료 |

메인 메뉴 진입 시 **시스템 현황 요약** 표시: 등록 시료 수, 총 재고, 전체 주문 수, 생산라인 대기 수

---

### 5.2 시료 관리 `[1]`

| 서브 메뉴 | 기능 |
|-----------|------|
| [1] 시료 등록 | 시료 ID·이름·평균 생산시간·수율 입력하여 시스템에 추가 |
| [2] 시료 조회 | 등록된 전체 시료 목록 표시 (현재 재고 수량 포함) |
| [3] 시료 검색 | 이름 등 속성으로 특정 시료 검색 |

---

### 5.3 시료 주문 `[2]`

1. 시료 ID, 고객명, 주문 수량 입력
2. 입력 내용 확인 후 [Y] 접수 / [N] 취소
3. 접수 완료 시 주문번호 자동 생성, 상태 = `RESERVED`
4. 재고 확인은 [3] 승인 메뉴에서 처리 (주문 시점에는 재고 확인 안 함)

---

### 5.4 주문 승인/거절 `[3]`

1. `RESERVED` 상태 주문 목록 표시
2. 처리할 주문 번호 선택
3. **재고 확인 자동 수행**:
   - **재고 충분** → 즉시 `CONFIRMED` 전환 (출고 대기)
   - **재고 부족** → 생산 라인에 자동 등록, `PRODUCING` 전환
4. **거절** 선택 시 → 즉시 `REJECTED` 전환

> 출고 대기(CONFIRMED)로 인해 추가 생산이 필요한 상황도 고려 필요

---

### 5.5 모니터링 `[4]`

**[1] 주문량 확인**
- 상태별(`RESERVED` / `CONFIRMED` / `PRODUCING` / `RELEASED`) 주문 건수 표시
- `REJECTED`는 유효 주문이 아니므로 제외

**[2] 재고량 확인**
- 각 시료별 현재 재고 수량 표시
- 주문 대비 재고 상태 판정:

| 상태 | 조건 |
|------|------|
| 여유 | `CONFIRMED` / `RESERVED` 처리 가능한 재고 |
| 부족 | 처리가 불가능한 수준의 재고 |
| 고갈 | 재고 수량 = 0 |

---

### 5.6 생산라인 조회 `[5]`

- 생산라인 1개 (단일 라인)
- **현재 처리 중**: 주문번호·시료·주문량·재고·부족분·실생산량·진행률·완료 예정 시간
- **대기 중인 주문 (FIFO 순)**: 순서·주문번호·시료·주문량·부족분·실생산량·예상 완료 시간

표기할 정보 수준은 자율적으로 결정 가능.

---

### 5.7 출고 처리 `[6]`

1. `CONFIRMED` 상태 주문 목록 표시 (번호·주문번호·고객·시료·수량)
2. 출고할 주문 번호 선택
3. 출고 완료 시 상태 `CONFIRMED` → `RELEASED` 전환
4. 출고 결과 표시: 주문번호·출고수량·처리일시·변경된 상태
